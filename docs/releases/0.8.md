# GameCAT 0.8 — pamięć tłumaczeniowa

Wersja rozwija funkcjonalność TM z 0.7, **bez modyfikacji istniejących
wpisów pamięci w bazach projektu**.

## Funkcje

- **TM → Wybierz zewnętrzną bazę TM…**: użyj istniejącego pliku SQLite lub
  utwórz nowy plik `.sqlite`/`.db`. Wybór zostaje zapamiętany w bazie
  projektu. Jeden zewnętrzny plik może być podłączany do wielu projektów,
  a podpowiedzi są ograniczane do ich par językowych.
- **TM → Użyj TM w bazie projektu**: powrót do wbudowanej pamięci. Zmiana
  aktywnego magazynu nie kopiuje ani nie usuwa istniejących par.
- **TM → Importuj TM (CSV/JSON)…** i **Eksportuj TM (CSV/JSON)…**:
  wymiana wszystkich par językowych aktywnej pamięci. Import w jednej
  transakcji; brak częściowego zapisu przy błędnym rekordzie. Duplikaty
  rozpoznawane po `(source, target, source_language, target_language)`.
- **Minimalne podobieństwo** w panelu TM: próg od 0% do 100%, zapisywany
  osobno dla projektu. Domyślne 45% zachowuje zachowanie z 0.7.
- **Zatwierdzenie segmentu (APPROVED)** automatycznie dodaje niepustą
  parę Source/Target do aktualnej pamięci TM. Kolejne zatwierdzenia
  nie powodują duplikatów.
- **TM → Analiza projektu względem TM…**: dotychczasowa analiza porównawcza
  (sekwencyjnie/wątki/procesy) i podział na przedziały dopasowania pozostają
  bez zmian. Pretranslacja umożliwia teraz ustawienie progu od 50% do 100%.
  Domyślnie pozostaje 100%, niższy próg wymaga potwierdzenia. Nigdy nie
  nadpisuje niepustych Targetów. Wyniki dla mniej niż 100% są **sugestiami
  wymagającymi ręcznej korekty i kontroli QA**; nie zostają zatwierdzone.

## Format CSV

UTF-8 lub UTF-8 z BOM; wymagane kolumny:

```csv
source,target,source_language,target_language,origin_project,created_at
"Take the sword.","Weź miecz.",en,pl,Kingmaker,2026-10-20T08:00:00+00:00
```

Wymagane: `source`, `target`, `source_language`, `target_language` (niepuste).
Opcjonalne: `origin_project`, `created_at` (ISO 8601). CSV jest cytowany
zgodnie ze standardem RFC 4180, więc przecinki i nowe linie w segmencie
nie rozdzielają pól.

## Format JSON

Najwyższy poziom jest tablicą obiektów:

```json
[
  {
    "source": "Take the sword.",
    "target": "Weź miecz.",
    "source_language": "en",
    "target_language": "pl",
    "origin_project": "Kingmaker",
    "created_at": "2026-10-20T08:00:00+00:00"
  }
]
```

Brak daty oznacza datę importu, brak nazwy projektu pochodzenia oznacza
`null`. Eksport zawiera wszystkie pola. JSON zachowuje Unicode i znaki
nowych linii.

## Zgodność i bezpieczeństwo

- Migracja projektu 0.7 do 0.8 dodaje tylko tabelę `tm_project_settings`.
  Domyślną pamięcią pozostaje tabela `translation_memory` w bazie projektu.
- Zewnętrzna TM **nie jest** tworzona ponownie, jeżeli wcześniej podłączony
  plik zniknął: otwarcie projektu zgłasza błąd i nie zapisuje nowej pustej
  bazy w jego miejscu.
- Import z błędnym rekordem nie aktualizuje pamięci ani wbudowanej, ani
  zewnętrznej. Zewnętrzny plik będący bazą projektu lub niepowiązaną bazą
  SQLite jest odrzucany.
- Pretranslacja ignoruje wpisy raportu analizy dotyczące innych źródeł.
  Istniejących tłumaczeń nie nadpisuje.
- Pliki przykładów: `sample_data/tm_sample.csv` i `tm_sample.json`.
