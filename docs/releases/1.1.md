# GameCAT 1.1.0 — architektura, wydajność, kontekst segmentów

**Baza:** GameCAT 1.0.2. **Schemat SQLite:** bez zmian. Otwieranie istniejących projektów nie wymaga migracji.

## Zakres

1. **Fasada `ProjectService`.** `MainWindow` nie odczytuje bezpośrednio `SegmentRepository` ani `TranslationMemoryRepository`. Dostęp prowadzi przez `get_segment`, `count_segments`, `get_tm_entries`, `tm_sources` i inne metody publiczne serwisu.
2. **Sugestie TM bez blokowania GUI.** Wyszukiwanie fuzzy uruchamiane przez `find_tm_matches_async()`; wynik trafia do panelu wyłącznie wtedy, gdy nadal dotyczy zaznaczonego segmentu i tego samego projektu. Kolejne zapytania anulują oczekujące, a spóźnione odpowiedzi są ignorowane. Dla aktywnej pary językowej używana jest pamięć podręczna wpisów TM, unieważniana przy operacjach TM przez `ProjectService`. Podłączenie zewnętrznej bazy i wybór magazynu są synchronizowane z odczytem cache.
3. **QA w tle.** `Ctrl+Shift+Q` oraz kosztowne indeksy filtrów `Błędy QA`/`TM 100%` nie wykonują skanowania w głównym wątku Qt. Po zmianie projektu, filtra lub tekstu nieaktualne wyniki są ignorowane. Skan QA projektu wyświetla informację o nieaktualnym wyniku, jeżeli Target zmieniono w jego trakcie. QA bieżącego segmentu również korzysta z workerów i publikuje tylko aktualne wyniki.
4. **Strumieniowe przetwarzanie.** `scan_segments` przechodzi iterator jednokrotnie, bez `list(segments)`. Eksporty w trybie projektowym TXT/CSV/TSV/JSON mogą przetwarzać uporządkowany iterator bez pełnego sortowania/materializacji (dla JSON list/dict zapis jest przyrostowy). Publiczne eksportery zachowują historyczne sortowanie, gdy dostaną nieuporządkowany zbiór. Przy eksporcie szablonowym i niektórych formatach strukturalnych nadal potrzebne jest buforowanie.
5. **Komentarze i kontekst.** `Segment.comment` ma edytowalne pole w `SegmentEditor`, z zapisem przez istniejący autosave. Edycja samego komentarza nie cofa statusu `REVIEWED`/`APPROVED`. `FormatProfile.comment_field` pozwala wskazać kolumnę CSV/TSV/XLSX, ścieżkę JSON lub tag/atrybut XML. Stare profile pozostają zgodne (`comment_field=''`). CSV ma osobny wybór kolumny kontekstu, a formaty płaskie eksportują komentarze. Eksport do oryginalnego szablonu aktualizuje wyłącznie Target i nie nadpisuje metadanych gry.

## Przykładowe mapowanie kontekstu

`sample_data/context_dialogues.json`:

```json
{
  "dialogues": [{
    "id": "guard_01", "en": "The gate is closed.", "pl": "",
    "speaker": "Strażnik przy głównej bramie"
  }]
}
```

Mapowanie JSON: `records_path=dialogues`, `key_field=id`, `source_field=en`, `target_field=pl`, `comment_field=speaker`.

Mapowanie XML: `records_path=.//entry`, `comment_field=@speaker` lub `comment_field=context`.

## Weryfikacja ręczna w Windows + PySide6

1. Otwórz projekt 1.0.2. Wybieraj szybko różne segmenty; lista TM musi odpowiadać ostatnio zaznaczonemu segmentowi. Zmień próg TM i sprawdź listę sugestii.
2. Włącz filtr błędów QA, edytuj Target, powróć na inny segment — filtr musi się odświeżyć bez zablokowania okna. Uruchom `Ctrl+Shift+Q`, a w czasie skanu zmodyfikuj segment: nie wolno opublikować nieaktualnego raportu.
3. Zaimportuj `sample_data/context_dialogues.json` z `comment_field=speaker`; sprawdź komentarz pod Target, zmień go i otwórz projekt ponownie. Zmiana kontekstu nie może cofnąć recenzji.
4. Sprawdź import CSV z kolumną `context`; eksport CSV/TSV/JSON powinien zachować komentarze. Eksport według oryginalnego szablonu nie może zmienić pozostałych metadanych gry.
5. Sprawdź otwarcie projektu 1.0.2 z zewnętrzną TM, autosave, zamknięcie aplikacji oraz kilkukrotny import/eksport.

## Ograniczenia

- Pełna lista segmentów pozostaje w pamięci GUI (`QListWidget`) na potrzeby interaktywnej edycji; ogromne projekty mogą nadal wymagać wirtualizacji listy w przyszłej wersji.
- Wyniki skanowania QA gromadzą zgłoszone problemy, bo muszą być pokazane w panelu.
- W trybach szablonowych JSON/XML/XLSX utrzymujemy oryginalną strukturę, dlatego odpowiednie dokumenty mogą nadal być buforowane w pamięci.
- Cache TM odświeża się po zmianach wykonywanych przez serwis. Jeśli zewnętrzna baza zostanie zmieniona poza GameCAT podczas działania aplikacji, podłącz ją ponownie, aby uzyskać nowy snapshot.
- Rzeczywiste testy widgetów wymagają zainstalowanego PySide6.
