# GameCAT 0.11 — formaty lokalizacji gier

Etap 0.11 rozszerza wymianę plików o **TSV, XLSX i XML**, a import JSON oferuje teraz **opcjonalne mapowanie pól zagnieżdżonych**. Format TXT/CSV/JSON używany w 0.10 nadal działa. Ustawienia mapowania są zapisane **osobno dla projektu i formatu** w jego pliku `.sqlite` (`project_format_profiles`), bez przechowywania kopii oryginalnych plików.

## Podstawowa obsługa

1. Otwórz istniejący projekt lub stwórz nowy.
2. **Plik → Importuj plik źródłowy…** i wybierz TXT / CSV / JSON / TSV / XLSX / XML.
3. Przy JSON możesz zaznaczyć **Klasyczny format JSON**, aby zachować zachowanie 0.10 (słownik `key: source` lub lista z `source`). Aby importować zagnieżdżoną strukturę, odznacz tę opcję i wypełnij pola mapowania.
4. Przy TSV i XLSX podaj nazwy kolumn z wiersza nagłówków (opcjonalnie nazwę arkusza). Przy XML ustaw XPath do rekordów i ścieżki elementów / atrybutów.
5. Możesz też wykonać **Plik → Importuj tłumaczenie…** z tych samych formatów; istniejące Source nie są zmieniane. Plik tłumaczeń może mieć tylko kolumnę Target i ID. Mapowanie importowanego tłumaczenia jest jednorazowe i nie nadpisuje profilu Source używanego do eksportu szablonowego. Jeśli brak ID, następuje dopasowanie według pozycji.
6. **Plik → Eksport** zapisuje wynik w formacie wymiany GameCAT (TXT, CSV, JSON, TSV, XLSX, XML). Nie jest to pełny plik oryginalnej gry; aby zachować oryginalną strukturę, użyj osobnej funkcji opisanej poniżej.

## Eksport zachowujący strukturę gry

1. Najpierw zaimportuj tekst źródłowy z odpowiednim mapowaniem (profil zapamiętuje SQLite).
2. Wybierz **Plik → Eksportuj według oryginalnego szablonu…**.
3. Wskaż **ten sam oryginalny plik**, którego teksty zostały zaimportowane (CSV/TSV/XLSX/JSON/XML).
4. Wskaż **nowy plik docelowy** — nie ten sam co źródłowy.
5. Program porównuje identyfikatory i tekst Source. Przy zmianie oryginalnych tekstów, zduplikowanych ID, brakującym wpisie lub różnicy źródła przerywa eksport bez modyfikowania pliku docelowego. Istniejące niezwiązane pola JSON/XML i kolumny XLSX/TSV pozostają zachowane. Nowe tłumaczenia zastępują wyłącznie pola Target.

**Uwaga:** ta funkcja jest przeznaczona dla *jednego pliku źródłowego odpowiadającego zawartości projektu*. Gdy projekt zawiera segmenty z wielu różnych plików, rozdziel je na osobne projekty lub eksportuj jako format wymiany. Eksport według szablonu nie próbuje automatycznie dopasowywać segmentów po podobieństwie treści.

## Przykładowe mapowania

### JSON zagnieżdżony

Dla `sample_data/game_structured.json`:

| Pole formularza | Wartość |
|---|---|
| Kolekcja | `data.dialogues` |
| Klucz | `id` |
| Source | `text.en` |
| Target | `text.pl` |

Konfiguracja jest dostępna także w `sample_data/profile_json_example.json`.

### XML

Dla `sample_data/game_structured.xml`: rekordy `.//entry`, klucz `@id`, Source `source`, Target `target`. XML zawierający deklaracje DTD / encje użytkownika jest odrzucany. Wpisy z zagnieżdżonym markupem *w polu Target* nie są nadpisywane, ponieważ program nie zna składni specyficznej dla gry.

### TSV

Tabela z nagłówkami `id`, `source`, `target`, opcjonalnie `context`. Prawidłowo rozpoznawane są cytowane pola wielowierszowe i Unicode.

### XLSX

Arkusz `Strings` z `id`, `source`, `target` oraz innymi kolumnami. Można wybrać inny arkusz. Przy eksporcie według szablonu pozostałe arkusze i elementy archiwum XLSX pozostają nienaruszone; arkusz z tłumaczeniami jest zapisywany ponownie. Program odrzuci zmianę komórki Target zawierającej formułę, zamiast ją usunąć. Makra `.xlsm` nie są obsługiwane.

## Ważne ograniczenia

- Ścieżki JSON zapisuje się jako nazwy pól rozdzielone kropkami; skomplikowane selektory JSONPath i indeksowanie tablic zagnieżdżonych nie są jeszcze obsługiwane.
- XML: tylko podzbiór XPath obsługiwany przez `xml.etree.ElementTree`. Serializacja może zmienić białe znaki i prefiksy przestrzeni nazw, choć elementy, atrybuty i treść pozostają. Dla gier wymagających byte-identical plików mogą być potrzebne osobne adaptery.
- XLSX: obsługiwane są popularne komórki `inlineStr`, `sharedStrings` i proste wartości; nie ma interpretacji formuł. Przy eksporcie zwykłym tworzony jest nowy arkusz z podstawową tabelą.
- Nie importuj kilku różnych dokumentów do jednej listy segmentów, jeśli planujesz później eksportować **jeden** oryginalny szablon — w wersji 0.11 brak śledzenia pochodzenia każdego segmentu osobno.
- Przed eksportem wynikowym zachowaj kopię zapasową pliku gry i przeprowadź QA placeholderów.
- Nie ma dodatkowej zależności runtime `openpyxl`: XLSX jest czytany i zapisywany za pomocą standardowej biblioteki OOXML/ZIP Pythona.
